# 人工复核清单（脚本查不了的东西）

> 脚本是**结构检查**，朱雀只测 AI 味。下面这些只能靠人（或模型带着清单）逐条过。
> **`QC_FULL` 每次全过；常规章只过标 ★ 的。**
>
> 这份清单是两份来源合并的：我们自己的"人工判断项"＋ InkOS v1.8.0 的 33 维度审计清单
> （该机制在它 master 上已删除，我们从旧版本还原）。**标 `[脚本]` 的那些已经有脚本查了，
> 列在这里是为了让你知道"这维度已经有人管"，不用重复劳动。**

> **执行分工（作者 2026-10-15 确认）**：本节条目由 **AI 代跑**（第三步 step4 一致性自检、每 10 章对照总纲、
> 完结核对都是 AI 执行），**人只保留抽查与终审**：
> - **AI 代跑（人抽查）**：不 OOC、关系/时间线承接、时间线算术、知识边界、禁止矛盾、钩子轮换、
>   声纹落点/语气、信息去重、概述替代场景/对话潜台词、每 10 章对照总纲、节奏护栏
> - **人终审（AI 只给证据）**：结局兑现、悬念揭晓、弧光闭环、伏笔语义回收（完结阶段，"写得好不好"只能人读）
> - **独家留给人的**：平台合规（敏感词/三观雷区，技能明确不做）、创作分岔拍板、审美终审

## A. 每章都容易踩的（★ 必过）

| 项 | 怎么判 |
| --- | --- |
| ★ **信息去重** | 同一个事实最多出现在"对话／内心／记录"三者中的**两处**，绝不三处都写 |
| ★ **旁白解释动机 / 解释性内心独白** | 身体反应或动作已表达情绪时，不再用内心独白／类比再解释一遍（“后颈发紧”后不写“领导问话最怕答太满”）；该让读者自己品的，旁白别下结论 |
| ★ **知识边界** | 角色只说他知道的事（对照角色档案的知识台账）——`[脚本]` 只查字段，不判语义 |
| ★ **概述替代场景** | 该演出来的被一句话总结掉（"两人聊了很久，达成了共识"）|
| ★ **只传递信息的对话** | 对话没有动机、没有风险、没有潜台词，只在搬信息 |
| ★ **语气像不像那个人** | 遮住名字，能不能看出是谁在说（声纹脚本只数次数，不判语气）|
| ★ **视角一致性** | 有没有跑出当前叙述视角／人称；同场多重要角色时**不得增加视角数量** |
| 无支撑的结论 | 先给判断、没有证据："他是个狠人"，可没有任何行为支撑 |
| 无场景证据的情绪标签 | "他很痛苦"，但前文没演过任何具体的痛苦 |
| 重复的解读 | 同一个意思被反复"解读"三四遍 |
| 装饰性细节 | 描写不承担功能：不给证据、不造压力、不显视角 |
| 通用过渡 | 段落靠连接词硬接，不靠因果／时间／动作接 |
| ★ **场景切入是否总从环境写起** | 每一场都"先写天气再写人"＝模板感；切入方式要换 |
| **外貌是否每次出场都描写** | 每次出场都描一遍＝凑字；只在该被看见时写 |
| **对话占比是否符合场景类型** | 冲突 60-80% ／ 日常 40-60% ／ 过渡 20-40%（`style_audit` 只查标签率，不判占比是否合场景）|
| `[脚本]` 词汇疲劳 | 黑名单 + 用词配额（`style_audit`）|
| `[脚本]` 段落等长／套话密度／公式化转折／列表式结构 | 连续同长度句、段长波动、单句段占比（`style_audit`）|

## B. 节奏与推进

| 项 | 怎么判 |
| --- | --- |
| ★ **每章至少推进一条主轴 + 一条支撑轴** | 节点 `axes:` 声明了，但**声明是否属实要看正文**（`[脚本]` 只查声明有没有写）|
| ★ **章末钩子是否真的勾人** | 钩子不靠"被提到"维持：要有人**依证据行动、付出代价、做出选择、或改变理解**；只被提及不算推进 |
| 爽点虚化 | 该兑现的只喊了口号，没落到具体动作与后果 |
| 流水账 | 事件按时间平铺，没有取舍、没有强调 |
| 节奏单调 | 连续几章同一情绪／同一强度（`[脚本]` 有序列级提示，但不计入必须改）|
| 支线停滞 | —— `[脚本]` 已查（`series_audit` 支线出勤），这里只确认"出场是否有效" |
| 弧线平坦 | 主角自我认识／处境有没有真的移动，还是只是"又过了一关" |
| 大兑现之后 | 有没有先写余波，再开下一轮升级（不要兑现完立刻换新目标）|

## C. 人物与关系

| 项 | 怎么判 |
| --- | --- |
| ★ **OOC（人设崩）** | 对照角色档案的**性格锁**与 OOC 红线 |
| 配角降智 | 配角为了推进剧情做了蠢决定（而不是因为他的动机与信息）|
| 配角工具人化 | 配角只在需要时出现、只为推动主角服务 |
| 台词失真 | 这台词像"作者在解释"，不像这个人在说话 |
| 利益链断裂 | 谁欠谁、谁怕谁、谁靠谁吃饭——关系变了但利益结构没跟上 |
| 关系动态 | 关系变化有没有落到具体小事上（而不是宣布"他们关系变好了"）|
| ★ **感情戏只推一小步** | 是否只落在具体小事上，没有一步到位 |
| 视角/称呼契约 | `[脚本]` 已查称呼契约（`continuity_check`），这里确认语气是否同步改了 |

## D. 世界与设定

| 项 | 怎么判 |
| --- | --- |
| ★ **设定冲突 / 世界规则一致** | 对照世界观与红线；跨书／跨卷规则是否一致 |
| ★ **时间线算术** | 事件发生日 vs **主角发现日**要分开记；倒计时不能回退（`[脚本]` 查了算术）|
| 数值检查 / 战力崩坏 | 数值与实力关系有没有跳变（`[脚本]` 不做，需人工）|
| 年代考据 | 道具、称谓、货币、技术是否合年代 |
| 重要物件的交接 | 物件被开启／移动／改变前，既定的**持有者、接触规则、可见交接**要在 |
| 禁止矛盾清单 | `[脚本]` 已逐条字面搜（`style_audit --forbidden`）|

## E. 读者视角与信息管理

| 项 | 怎么判 |
| --- | --- |
| ★ **信息越界（未来信息泄露）** | 有没有写到"这个时点还不该知道"的事 |
| 读者期待管理 | 这一章承诺了什么？有没有兑现或**故意延迟**？延迟要有理由 |
| 章节备忘偏离 | 本章实际写的，与节点里计划的（beat／场景卡）是否一致 |
| 三幕比例与卷节拍 | 是否走偏（`[脚本]` 不判）|
| 空话密度 | 这句话能删吗？能搬到别的章节吗？是不是正确废话？|
| ★ **比例不得靠复述满足** | 支线比例要落成场景／对话／行动／证据／关系变化，**不能靠复述百分比** |

## F. 平台与合规

| 项 | 怎么判 |
| --- | --- |
| 平台合规 | 敏感词、三观雷区（绿帽／送女／夹带私货）——**技能不做合规扫描，这是作者的责任** |
| 章节号元叙述 | `[脚本]` 已查正文里冒出"第N章"这类结构泄漏（`style_audit`）|
| 单章字数 | `[脚本]` 只判下限；上限不判不提示（P002）|
